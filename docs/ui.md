# UI contract

Offline-data retention is requested automatically at launch. Settings → Backup offers a visible Keep data on this device / Behåll data på den här enheten button to retry, with inline status reporting whether the browser grants it. Help explains that clearing browser data can still remove saved places. Export/Import have equal widths with a 12px gap on wider screens and stack on narrow phones; a separate note by Export identifies backup files as unencrypted. Backups and account sync remain the recovery options.

Active group libraries show a Participants button with the current member count. It opens Family sharing for that group. The participant list shows all members, marks the owner and the signed-in user, and refreshes while open. Only the owner sees removal controls for other members; removal requires a confirmation naming the selected person. Removing someone ends cloud access to that group while preserving downloaded copies and membership in other groups.

An account may participate in several named groups (up to twenty, with ten people in each). The library selector lists private places, each active group and retained read-only group copies. Settings → Family sharing has a Group selector for management, plus Join or create another group. Codes, approvals, invitations, leaving and ownership actions apply to the selected group. A private place's Copy to family menu lists explicit group destinations. Switching libraries preserves that group's draft and pending writes without copying content between groups.

Family sharing lives in Settings. Sign in, name/create a family library, then create a four-digit invitation code. The recipient opens Places from their own Home Screen, signs in and enters it under Family sharing. They request to join; the owner verifies the displayed identity and explicitly approves it. Both screens refresh while open. The code lasts ten minutes, and can be copied or read aloud. This avoids relying on external links opening an installed iPhone web app. A compact library selector separates Private places from named groups and retained read-only copies. It uses a fixed lock/group icon and wrapping labels, with all choices in one menu. Save position writes to the selected library. Existing private places offer Copy to family; the original stays private. Photos, categories, edits and deletions are shared. The owner can revoke invitations, remove members, transfer ownership or delete the family. Members can leave. Cached libraries become read-only with export when access ends. First sign-in reconciles the private guest library separately; joining groups does not move private data.

Dark is the default for a new installation; existing saved theme choices are preserved. Light/System and English/Swedish are device preferences. Semantic CSS tokens, readable typography and restrained surfaces distinguish Places from Music's styling. Primary targets are at least 56px; regular targets at least 48px.

The GPS review preference uses a labelled, right-aligned switch with an explicit refinement description below. Its persisted value and keyboard access follow the native checkbox; forced-colour modes retain the native control. Install Places and Privacy use matching 48px disclosure rows and chevrons. Check for updates remains outlined. A compact footer contains About Voltura Places and Source on GitHub links with wrapping labels and 48px targets. Licensing copy stays outside the in-app footer.

Phone typography prioritizes reading outdoors: normal text and action labels are 18px, Save position and place names 20px, supporting information 16px, and field/tab labels 17px at the default browser size. Use rem units so these sizes can scale. Search and form fields are at least 18px. Paired actions stack on phones; settings navigation uses a single tab row only while its full labels fit, otherwise a full-width native section selector. Preserve browser zoom, scrolling and complete labels rather than shrinking text to fit.

Visual depth stays restrained: a static ambient background, softly graded surfaces and primary actions, consistent highlights/shadows and distinct category tints in both themes. Cards separate identity from map actions with a quiet divider. Keep readable text on solid surfaces; no decorative animation, marketing panels or artificial startup delays.

Position details adapt to the card's available width. A small pin and category precede the full wrapping name. The mobile sheet uses a generic Place details title so long names appear only once. Coordinates have an adjacent 48px copy target. Saved date and accuracy, and the two map actions, share rows when space permits and stack in narrower cards. Share/Edit retain labels in equal-width columns. Content determines height without shrinking controls; buttons are at least 48px high, section gaps are compact, and padding is 16px in narrow cards or 24px in wider cards.

Share `https://places.voltura.se/?lang=sv` to open directly in Swedish, overriding browser language and previous preferences. `?lang=en` opens English. The choice is persisted normally, and the language parameter is consumed after launch so a later Settings change remains effective. Other query parameters and shared-place fragments are preserved; unknown language values are ignored.

All promotional-site app links carry the displayed page language: Swedish `/places/sv/` links use `?lang=sv`, while English `/places/` links use `?lang=en`. This includes navigation, the hero button and the installation button.

Save position stays in a safe-area bottom dock. Tap requests fresh high-accuracy GPS, shows progress and permits cancel. After local commit it opens a non-blocking editor. Defaults use localized date/time and last-used category (Other initially). Closing keeps the saved place. Editor drafts persist separately.

Cards expose name/category/date and Open maps. Search/category/sort use ordinary controls and scrolling. Desktop adds a details pane; mobile uses a sheet. Edit/share/delete are secondary. Destructive actions require confirmation. Place deletion uses a themed modal sheet naming the selected place with Cancel focused initially and an explicit Delete action. Escape, close and backdrop dismiss without deleting; account/library changes discard the pending confirmation. Core flows do not depend on gestures/hover/animation/map canvas.

Keep the application functional and quiet: no slogans, decorative empty-library illustration, exploration copy, or unselected details welcome panel. A genuinely empty library keeps Your places, one short Save position instruction and Add place with details, hiding the zero count, header plus, search, sort and filters. Add place opens the details editor and requires GPS or a photo location; it is not manual coordinate entry. Search with no matches retains the populated-library tools. Show Works offline once in the save dock. Desktop uses a centred library until a selected place needs the details column. Product promotion belongs on the separate promotional site.

First map opening asks for a provider and remembers it. Map links open a new tab/window with no opener or referrer, both from the provider picker and when using the remembered provider, keeping Places open. OS/browser handlers may hand the link to an installed map app instead. Other outgoing content links (promo/source) also open separately; sign-in redirects continue in the current app context to complete authentication. Sharing presents the irrevocable snapshot disclosure before share/copy. Settings separates preferences, categories, backups and accounts. Reconciliation/conflicts are explicit decisions. Status distinguishes local saving, pending operations, successful sync and failure.

Modal sheets keep their header/close button visible and scroll only their inner content. Scrollbars stay inside the rounded panel, follow the theme, and do not scroll the background page. Normal page scrolling resumes when every sheet is closed.

Settings stays anchored 20px from the top on desktop and phones so switching sections does not move its header. Its compact header preserves a 48px close target; the body has 16px phone / 24px desktop padding and scrolls within the viewport with bottom safe-area clearance. When navigation uses a dropdown, the selected section serves as the sole section heading: a 56px minimum row with a 22px outline icon, semibold wrapping label, 12px gaps and an outline down chevron. Its full row opens navigation, with matching option icons and a right-aligned selected checkmark in customizable native pickers. Content begins 16px below, without a repeated heading or decorative family icon. Tab navigation retains separate section headings, including the family heading. Signed-out visitors see a concise privacy description and a full-width Sign in to share action of at least 48px. Button, select, disclosure and form-control labels cannot be text-selected; text inputs and textareas retain selection and copying.

The page suppresses horizontal overscroll so a sideways drag cannot move the library. Settings content scrolls vertically and contains its gestures; pinch zoom remains available. The primary GPS button is labelled Save position in English and Spara position in Swedish, including the empty-library instruction.

Toasts belong to the active modal when one is open, so copy confirmations/errors remain visible and accessible above its backdrop. Closing the modal returns remaining feedback to the page.

Account settings explicitly say Signed in or Not signed in. A signed-in account shows each distinct identity label once, explains automatic sync, and keeps Sync now/Sign out together. Optional linking lives under Sign-in methods and uses Link labels; Sign in with Google / ChatGPT labels are reserved for signing in (Logga in med Google / ChatGPT in Swedish). The cloud icon sits inside the account status box, to the left of the status and identity; the signed-out cloud has an inset diagonal slash from bottom left to top right.

Installed launches open the library. Service-worker updates wait for acceptance and preserve drafts/pending data. Private APIs are never HTTP-cached. Promo has no service worker. Physical-device/daylight checks remain distinct from emulation.

Bookmarks/installed launches use the dedicated platform icons. iPhone/iPad launch-image links select a device/DPR, system appearance and orientation; the OS controls when they appear and may cache older installed artwork. There is no artificial startup delay or in-app splash overlay. Promo sharing uses localized Open Graph and large-image Twitter metadata with absolute public image URLs, dimensions and alternative text. App sharing also has a branded preview.

Users never type latitude/longitude. Save position requests the phone/browser location API and immediately persists the returned fix. Add place and the editor offer Use current location; a selected photo with valid embedded GPS offers Use photo location as an explicit choice. Photos without readable GPS explain the fallback. Existing positions are not silently moved by attaching a photo. Accuracy is reported from the device, not promised; a new GPS selection updates accuracy/capture time and photo positions have unknown accuracy.

Quick save and editor GPS reject invalid/stale positions and recover from synchronous browser errors without saving or leaving a busy control stuck. Read-only family copies disable add/edit/conflict actions while retaining viewing, map handoff and export.

Location acquisition uses a bounded high-accuracy watch until a fresh valid fix arrives, then stops that acquisition after quick save/editor selection. Permission becoming granted or returning to the visible app can restart a stalled acquisition up to twice. Unavailable/timeout results are acquisition failures, not permission denial: retry after 1, 3 and 6 seconds, then keep the current watch alive until a valid fix or the original one-minute deadline. A valid fix cancels pending retries; explicit denial stops immediately. Late callbacks from an earlier watch are rejected. Unsupported Permissions APIs do not block acquisition. Cancel, account/library changes and closing the editor remove watches and permission/foreground listeners. The live review uses the same recovery while keeping its explicit confirmation and one-minute bound. Physical iPhone permission/OS-location behavior still requires device verification.

The just-saved editor continues high-accuracy GPS refinement for up to one minute while open. Selecting Use current location or confirming GPS review in an editor also starts refinement. Only fresh, valid fixes with a strictly smaller reported accuracy radius replace the selected coordinates, accuracy and capture time together; equal/worse fixes and acquisition failures retain the best selection. The accuracy text updates with a polite status announcement. Refinement changes the editor draft only: Save changes commits the improved selection, while Done/close retains the already saved place. Opening an older place does not start GPS automatically. Save, close, choosing a photo location, a new GPS request, account/library changes, denial or the one-minute deadline stop refinement and reject late callbacks. This bounded continuation follows an explicit GPS action; it does not track locations after the dialog closes.

Preferences includes Review GPS accuracy before saving (off by default, persisted per device). When on, Save position and the editor's Use current location open a live review instead of accepting the first fix. Request high-accuracy watchPosition with no cached fixes. Display the latest valid estimate in metres, its age and four qualitative bars: ≤10 m, ≤20 m, ≤50 m, >50 m. These are UI thresholds, not guarantees or GPS signal strength. Estimates may improve or worsen as fresh fixes arrive.

Distance units is a separate persisted preference: Metres (m, default) or Feet (ft). It applies to the live review, editor and saved-place details. Round displayed radii upward; unit selection never changes stored metre accuracy, coordinates, quality thresholds or backup/sync data.

The user confirms Use this position when satisfied; no place is created before confirmation. An editor confirmation updates only its draft until Save changes. Cancel preserves the library/editor draft. Reject invalid fixes and positions older than 15 seconds; disable confirmation once a displayed fix becomes stale. Stop watching on close, confirmation, account change, a terminal error, or after one minute. Retry starts a fresh bounded session. Permission/timeout/unavailable errors remain recoverable. Quick save uses the first valid position when the option is off.

Each editor offers Take photo (rear-camera capture hint), Choose photo (normal image picker), preview and Remove photo. One compressed image belongs to each place and follows saved drafts, offline use, cloud sync and JSON backups. Unsupported image formats show recovery feedback without replacing the previous photo. Native capture behavior depends on the device/browser.

Visible tabs check for updates every minute and on foreground/reconnection, with a manual Check for updates action in Preferences. Prompts appear above Settings or inside the editor. Accepting an update flushes drafts before all controlled tabs reload. Older clients need one refresh to receive this update-checking behavior.

First use offers Sign in or create account and Continue without an account. Choosing either dismisses the offer persistently; closing it selects guest use. Signing in creates an account through the normal verified provider flow when needed, without another registration form. Guest users always have a visible Sign in action in the header. Existing signed-in users do not see the first-use choice. Guest saving, offline use and backups remain available.

Categories keeps New category above the list without repeating the navigation label. Rows are at least 60px and grow for wrapping names; fixed colour dots and 48px edit/delete columns keep every pencil aligned, including Other's empty delete slot. Deletion confirmation explains that places move to Other.
All dropdowns use app-coloured selected, hover and keyboard-focus states, with themed pickers in browsers supporting customizable native selects; other browsers retain their native picker. Grouped preference rows use a thin inset keyboard-focus indicator following the group corners.

Appearance, Language, Preferred map app and Distance units share a compact outlined group with subtle dividers. Each row shows its label, wrapping current value and a right chevron; the entire row opens the native select, retaining keyboard and screen-reader access. Rows grow for long translations and enlarged text.

The populated library uses 16–24px section gaps, one search/sort row and horizontally scrolling phone category pills with complete labels. Compact cards keep a fixed marker, wrapping names, maps aligned to the content edge and overflow at the right. The account control uses an account icon; signed-in status adds a small dot. The save dock names the private/shared destination; its measured height, including wrapping text and the safe area, determines list bottom padding so the last card clears it.
